# ESP32 Firmware Download & WSS Certificates Guide

Complete guide for auto-generating and downloading ESP32 firmware with WSS (WebSocket Secure) certificates. **HTTP has been removed for improved security - only WSS is available.**

---

## 🎯 What's Included in Downloaded Package

When you click the download link or call the firmware endpoint, you get a complete ZIP file containing:

```
ESP32-ABC123_firmware.zip
├── src/
│   └── main.cpp                 # Main ESP32 sketch
├── include/
│   ├── config.h                 # Device config (device IDs, credentials)
│   ├── certificates.h           # WSS certificates (auto-generated)
│   ├── ble_provision.h          # BLE provisioning code
│   ├── mqtt_manager.h           # MQTT permanent + temporary connections
│   └── local_server_wss.h       # WebSocket Secure (WSS) server
├── platformio.ini               # PlatformIO project config
├── library.json                 # Arduino library metadata
└── README.txt                   # Instructions
```

> **🔒 Security First:** HTTP has been completely removed. All local network communication uses WSS (WebSocket Secure) with self-signed certificates.

## 🔐 WSS Certificates (Auto-Generated)

Each device gets **unique, self-signed certificates** for secure WebSocket communication (port 82).

### Certificate Details
- **Type:** Self-signed X.509 certificates
- **Common Name:** `<device_id>.local` (e.g., `ESP32-ABC123.local`)
- **Validity:** 10 years
- **Encryption:** RSA 2048-bit
- **Generated by:** Server on-demand
- **Location in ESP32:** Stored as hex arrays in `certificates.h`
- **Usage:** WSS TLS/SSL encryption for local network

### Auto-Generation Process
```
Server receives registration:
  ↓
Generate private key (RSA 2048)
  ↓
Generate self-signed certificate (CN = device_id.local)
  ↓
Convert to hex arrays (for C++ embedding)
  ↓
Include in firmware package
  ↓
Device uses for WSS on port 82
```

## 📥 Download Workflow

### Step 1: Register Device
```bash
curl -X POST http://localhost:3000/api/factory/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "secure_password",
    "relay_count": 2
  }'

# Response:
{
  "device_id": "ESP32-ABC123",
  "namespace": "ns_19e0fc21e130476e",
  "firmware_download": "http://localhost:3000/api/factory/generate-firmware/ESP32-ABC123",
  "access_token": "eyJhbGc..."
}
```

### Step 2: Download Firmware Package
```bash
# Option A: Using firmware_download URL from response
curl -O http://localhost:3000/api/factory/generate-firmware/ESP32-ABC123

# Option B: Direct download
wget http://localhost:3000/api/factory/generate-firmware/ESP32-ABC123 \
  -O ESP32-ABC123_firmware.zip
```

### Step 3: Extract Package
```bash
unzip ESP32-ABC123_firmware.zip
cd ESP32-ABC123_firmware
```

## ⚡ Flash to ESP32

### Using PlatformIO (Recommended)

1. **Install PlatformIO CLI:**
   ```bash
   pip install platformio
   ```

2. **Upload firmware:**
   ```bash
   cd ESP32-ABC123_firmware
   pio run -t upload -e esp32-wroom-32
   ```

3. **Monitor serial output:**
   ```bash
   pio device monitor
   ```

### Using Arduino IDE

1. **Copy files to Arduino sketch directory:**
   ```
   MySketch/
   ├── MySketch.ino          (copy main.cpp here)
   └── libraries/
       ├── config.h
       ├── certificates.h
       ├── ble_provision.h
       ├── mqtt_manager.h
       └── local_server_wss.h
   ```

2. **Select Board:**
   - Tools → Board → ESP32 Dev Module

3. **Select Port:**
   - Tools → Port → /dev/ttyUSB0 (Linux/Mac) or COM3 (Windows)

4. **Upload:**
   - Click Upload button

## 🚀 First Boot

### What Happens
1. ESP32 starts
2. Loads factory device ID and namespace from `config.h`
3. Starts BLE advertisement (look for "IOTYK-ABC123")
4. Waits for WiFi credentials via BLE
5. Once WiFi connected, loads MQTT credentials from NVS
6. Starts all services (MQTT, WSS server)
7. Published status to broker

## 🌐 Local Network Access

Once device is online and connected to WiFi, use **WebSocket Secure (WSS)** for encrypted local communication.

### WebSocket Secure (TLS Encrypted) ✅
```javascript
// Browser/JavaScript
const ws = new WebSocket(`wss://ESP32-ABC123.local:82`);

ws.onopen = () => {
  ws.send(JSON.stringify({
    token: "your_local_token",
    cmd: { power: "on" }
  }));
};

ws.onmessage = (event) => {
  const state = JSON.parse(event.data);
  console.log("Device state:", state);
  // Output: { relays: ["on", "off"], wifi: true, rssi: -65, fw: "1.1.0" }
};
```

### Python Client Example
```python
import websocket
import ssl
import json

def on_message(ws, message):
    state = json.loads(message)
    print("Device state:", state)

ws = websocket.WebSocketApp(
    "wss://ESP32-ABC123.local:82",
    on_message=on_message,
    sslopt={"cert_reqs": ssl.CERT_NONE}  # Accept self-signed cert
)

ws.send(json.dumps({
    "token": "your_local_token",
    "cmd": {"relay": 1, "power": "on"}
}))

ws.run_forever()
```

## 🔧 Customization

### Change Relay Count
When registering device:
```bash
curl -X POST http://localhost:3000/api/factory/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "admin@example.com",
    "password": "pass",
    "relay_count": 4          # 4 relays instead of 1
  }'
```

GPIO pins auto-assigned: 26, 27, 28, 29, ...

### Change MQTT Broker
Update `.env`:
```
EMQX_BROKER=your-custom-broker.com
EMQX_PORT=8883
```

Certificate Common Name automatically set to device ID.

## 🔐 Certificate Validation

Since certificates are self-signed:

**Mobile/Web Apps:**
- Accept self-signed certificate in your TLS/SSL settings
- Certificate pinning available (store certificate public key)
- Trust chain: self-signed root

**Python/Node.js:**
```python
# Disable SSL verification (development only!)
sslopt={"cert_reqs": ssl.CERT_NONE}
```

**Browser:**
- May show security warning (expected for self-signed)
- Trust the certificate for local development
- Not suitable for production without proper CA certificates

## 🚨 Troubleshooting

### Device won't connect to WiFi
- Check BLE provisioning data format (SSID,PASSWORD)
- Verify WiFi network is 2.4GHz (ESP32 limitation)
- Monitor serial output for errors

### Can't reach WSS endpoint
- Verify device IP: `ping ESP32-ABC123.local`
- Check firewall (port 82 must be open)
- Ensure WiFi is connected (check serial output)
- Verify token matches

### Certificate validation errors
- Use `sslopt={"cert_reqs": ssl.CERT_NONE}` in Python
- In browser, explicitly trust the certificate
- No need to import certificates - built into firmware

### MQTT connection fails
- Check EMQX broker is running and accessible
- Verify credentials in config.h
- Check MQTT port (8883 with TLS)

     ▼

     ▲                         ▲
